# 예소 가상 디바이스 (Virtual Device)

하드웨어 없이 **실제 펌웨어 C++ 코드를 PC에서 그대로 실행**하고, 그 화면을 브라우저에 띄우는 시뮬레이터입니다.
UI를 따로 흉내 낸 것이 아니라서 화면·애니메이션·루틴 규칙·보상·성장·서버 동기화가 기기와 **픽셀 단위로 같습니다**.

```
브라우저 (simulator/web)                     yeso-sim.exe (PC)
┌───────────────────────┐   HTTP 127.0.0.1   ┌──────────────────────────────────────────┐
│ 240×320 canvas        │ ◀── /api/frame ─── │ firmware/…/src  ← 수정 없이 그대로 컴파일   │
│ D4 / D5 / D6 버튼      │ ─── /api/buttons ▶ │   domain · application · presentation      │
│ 부저(Web Audio)        │ ◀── /api/status ── │   content · generated · DemoSession         │
│ USB 콘솔 / 개발자 패널  │ ─── /api/command ▶ │ simulator/src  ← platform/esp32 대체          │
└───────────────────────┘                    │   LCD·버튼·부저·절전·플래시·HTTP              │
                                             └───────────────┬──────────────────────────┘
                                                             │ WinHTTP (CORS 무관)
                                                             ▼
                                                 http://52.79.82.17/device-api/v1/…
```

## 1. 실행 방법

PowerShell에서 저장소 루트 기준:

```powershell
.\simulator\run.ps1
```

- 처음 실행하거나 C++ 코드가 바뀌면 자동으로 빌드합니다(약 15초). 빌드가 끝나면 브라우저에서 `http://localhost:8080` 이 열립니다.
- 종료: 실행 창에서 `Ctrl+C`

| 옵션 | 용도 |
|---|---|
| `-Mock` | 로컬 모의 API 서버(`:9090`)도 함께 켬. 실서버 없이 페어링과 동기화를 시험할 때 사용 |
| `-Lan` | 같은 Wi-Fi의 휴대폰에서 `http://<PC IP>:8080` 으로 접속 가능 (시연용) |
| `-Data 이름` | 별도 기기로 실행 (UID·페어링·기록이 `simulator/data/이름` 에 따로 저장) |
| `-Rebuild` | 강제 재빌드 |
| `-Port 8081` | 포트 변경 (여러 대 동시 실행 시) |

**필요한 것:** MSYS2 g++ (`C:\msys64\ucrt64\bin`, 이미 설치됨), Git Bash, Python(모의 서버용), 그리고 `simulator/assets/ui.pak`.
`ui.pak`(7 MB, CRC `dad8398c`)은 이 저장소에 없어서 `Downloads\Yeso2026-master\…\assets\packed\ui.pak` 에서 복사해 두었습니다. 다른 PC에서 실행하려면 이 파일도 같이 옮겨야 합니다.

### 3D 기기 화면

`http://localhost:8080/3d.html` (개발자 패널 상단 링크로도 이동)

- 기기 형상은 제품 CAD 내보내기 파일 **`web/models/device.glb`(시연용.glb, 9.4 MB)를 그대로 불러옵니다**. 앞·뒤 케이스, 버튼 3개, 디스플레이 모듈만 표시하고, 내부 부품(보드·스위치·부저 등 노드 4~76)은 숨깁니다.
  - 실측 59.9 × 80.4 × 33.4 mm. 노드 번호는 `3d.js`의 `PART`에 있습니다 (앞 케이스 0, 뒤 케이스 78, 버튼 2·3·1, 디스플레이 77).
  - 색상은 재질만 바꿉니다 (렌더의 7가지: 화이트·퍼플·블랙·핑크·그린·블루·옐로).
  - 왼쪽 옆면 아래쪽의 제품코드 스티커는 뒤 케이스 곡면에 광선을 쏴서 표면을 따라 붙입니다. 모든 색상 공통입니다.
  - 모델 파일을 바꾸면 노드 번호가 달라질 수 있으니 `PART`를 함께 확인해야 합니다.
- LCD에는 펌웨어 프레임버퍼가 그대로 텍스처로 들어가고, 3D 버튼을 클릭하면 실제 입력 경로(디바운스, 화면 컨텍스트)를 그대로 탑니다.
- 드래그로 회전, 휠로 확대, 색상 7종, 스트랩 표시, 부저 소리와 진동 효과, 절전 시 화면 꺼짐, 휴대폰 세로 화면을 지원합니다.
- Three.js는 CDN(jsdelivr, `three@0.160.0`)에서 불러오므로 **인터넷 연결이 필요**합니다.

### 조작

| 동작 | 마우스 | 키보드 |
|---|---|---|
| 이전 (D4) | ◀ 버튼 | `←` 또는 `A` |
| 확인 (D5) | ● 버튼 | `Space` / `Enter` / `S` / `↓` |
| 다음 (D6) | ▶ 버튼 | `→` 또는 `D` |

오른쪽 패널에서 상태, 페어링, 데모, 설정(Wi-Fi·모션·자동 절전·소리), USB 콘솔을 다룹니다. 콘솔에서 `help` 를 입력하면 명령 목록이 나옵니다.

### 실서버 페어링 순서

1. 앱에서 이 기기용 **10자리 페어링 코드**를 발급
2. 패널 **서버 연동 → 페어링 코드 입력 → 페어링** (콘솔에서는 `api pair 0123456789`)
3. 상태가 `연동됨` 이 되면 5분마다, 그리고 루틴 상태가 바뀔 때마다 자동 동기화. 바로 하려면 **지금 동기화**

기기 UID는 처음 실행할 때 `YESO-xxxxxxxxxxxx` 형식으로 무작위 생성되어 `simulator/data/<이름>/api.txt` 에 저장됩니다(실기기의 eFuse MAC 역할).

### 서버 없이 시연하기

- **데모 시작**: 펌웨어 내장 `DemoSession` 실행. "외출 준비" 루틴 1개, 가상 시계(2026-01-01 09:00 KST), RAM에만 저장
- **+1분 / +10분 / +1시간 / +2시간**: 가상 시간을 빨리 감기(마감 경고, 시간 초과 확인용)
- `-Mock` 실행 후 콘솔에서 `api reset-uuid` → `api endpoint http://127.0.0.1:9090` → `api pair 1234567890` 을 입력하면, 실서버와 같은 프로토콜로 1분 뒤 시작하는 루틴을 받습니다. 원래 서버로 돌아가려면 `api reset-uuid` → `api endpoint http://52.79.82.17` 를 입력합니다.

## 3. 기기와 다른 점 (시뮬레이터에서 바꾼 부분)

`platform/esp32/` 만 바꿨습니다. 동작 규칙(언제 그리고, 입력을 받고, 동기화하고, 절전하는지)은 `ProductRuntime.cpp`, `DeviceNetwork.cpp` 를 한 줄씩 옮겼습니다.

| 기기 | 시뮬레이터 | 비고 |
|---|---|---|
| ST7789 LCD | 240×320 RGB565 프레임버퍼 → canvas | 같은 버퍼를 그대로 전송 |
| 버튼 D4/D5/D6 + FreeRTOS 5 ms 입력 태스크 | HTTP로 받은 버튼 상태 + 5 ms 샘플링 재현 | 네트워크 지연에 대비해 최소 60 ms 누름 유지 |
| 부저 (NPN, 80 ms) | Web Audio 2.7 kHz 비프 + 화면 위 표시등 | |
| Light sleep | 화면 꺼짐 오버레이, 버튼이나 타이머로 깨어남 | 자동 절전 60초는 펌웨어 기본값 |
| FFat `state-a/b.bin` + NVS 세대 마커 | `simulator/data/<이름>/` 파일 | 저장 형식(StateCodec)은 같음 |
| NVS `routine-api` | `api.txt` | |
| SNTP 시계 | PC 시계 (항상 동기화된 상태) | `clock offset <초>` 로 실시간 모드에서도 시각 이동 가능 |
| Wi-Fi | 항상 연결 (`wifi off` 로 끊김 흉내) | |
| HTTPClient | WinHTTP | 브라우저가 아니라 PC 프로그램이 호출하므로 **CORS와 무관** |
| BLE 프로비저닝, USB 에셋 업로드, `storage` 명령 | 없음 | |
| eFuse MAC 기반 UID | 무작위 UID를 파일에 저장 | |

펌웨어 버전은 BLE 개발 빌드와 같은 `0.9.0-ble-dev` 로 보고합니다.

## 4. 발견한 것 / 확인이 필요한 것

### ✅ 핀 기준: 펌웨어 `HardwareConfig.h` 로 확정 (2026-10-31)
LCD SCLK **D9**, 부저 **D8**, 버튼 **D4/D5/D6**(이전/확인/다음, D6 = GPIO43 = UART0 TX). `docs/wiring/` 배선도도 이 기준으로 고쳤습니다. 시뮬레이터도 같은 기준입니다.

### 🟡 UX 규칙 확인 필요
- **자동 절전 시간**: HANDOFF 시나리오는 "10초 무입력 → 화면 끔"인데 코드는 `idleMs_=60000`(60초)입니다.
- **알림 직후 절전**: 루틴 시작이나 마감 경고 알림은 무입력 타이머를 초기화하지 않습니다. 마지막 조작 후 55초에 알림이 오면 5초 뒤 화면이 꺼질 수 있습니다(시뮬레이터에서 재현됨). 알림 때 `activityAt_` 를 갱신할지 정해야 합니다.

### ⏳ 아직 못 한 것
- **실서버 실제 페어링**: 유효한 페어링 코드가 필요합니다. 위 "실서버 페어링 순서"대로 하면 바로 확인할 수 있습니다.
- **Emscripten(WASM) 빌드**: 자동 실행 권한 정책 때문에 emsdk 다운로드·설치가 막혀서 PC 호스트 방식으로 만들었습니다. 지금 방식은 서버 호출을 PC 프로그램이 하므로 **CORS 수정 없이도 동작합니다.**

## 6. 파일 구성

```
simulator/
├── run.ps1                 실행 (자동 빌드 + 브라우저 열기)
├── scripts/build.sh        g++ 빌드 (변경된 파일만 다시 컴파일)
├── scripts/mock_server.py  로컬 모의 API (claim/sync)
├── src/SimRuntime.*        ProductRuntime 이식 (화면 갱신, 입력, 절전, 데모, 콘솔 명령)
├── src/SimNetwork.*        DeviceNetwork 이식 (claim/sync 상태 머신, 재시도, ack)
├── src/HttpClient.*        WinHTTP POST
├── src/FileSlots.*         FlashSlots 이식 (A/B 스냅샷, 세대 마커, 설정 파일)
├── src/Console.h           USB Serial 대체 (웹 콘솔로 전달)
├── src/main.cpp            HTTP 서버 + 메인 루프 (단일 스레드)
├── web/                    index.html · style.css · app.js (2D + 개발자 패널)
│                           3d.html · 3d.css · 3d.js · device-link.js (3D 기기), models/device.glb (CAD 모델)
├── assets/ui.pak           화면 에셋 팩 (원본 프로젝트에서 복사, git 커밋 여부 결정 필요)
├── build/                  빌드 결과 (git 제외)
└── data/                   기기 저장소 (git 제외)
```

`firmware/` 아래 파일은 하나도 수정하지 않았습니다.
